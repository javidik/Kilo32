# KiloProxyPool — автономный пул с встроенным Tor

Пул работает локально на комплектном Node.js и не подключается к серверу владельца. В него встроен официальный Tor Expert Bundle для Windows i686 (Tor 0.4.9.15): Tor daemon, GeoIP/GeoIPv6 и pluggable transports. Tor запускается как отдельный локальный процесс вместе с Kilo и останавливается при завершении CLI.

## Быстрый запуск через Tor

1. Скопируйте `config.example.json` в `config.json`.
2. Задайте собственные `clientAuth.username` и `clientAuth.password`.
3. Оставьте `tor.enabled: true`; при необходимости добавьте свои upstream в `upstreams`.
4. Запустите `kilo`.

Когда `tor.enabled` включён, KiloProxyPool автоматически запускает локальный Tor и использует `socks5h://127.0.0.1:19050`. По умолчанию `tor.exclusive: true`: весь проксируемый трафик Kilo идёт только через Tor, без случайного перехода на обычные upstream. Если явно задать `exclusive: false`, Tor и обычные upstream будут участвовать в общем пуле. DNS-имена передаются Tor для удалённого разрешения. Сам локальный HTTP-прокси остаётся на `127.0.0.1:17890` и защищён Basic-аутентификацией.

## Bridges

- Можно указать статические строки `Bridge ...` в `tor.bridges`.
- Для еженедельного обновления можно задать `tor.bridgeFeedUrl` — HTTPS-адрес собственного текстового feed, содержащего только строки `Bridge ...` (по одной на строку; поддерживаются vanilla, obfs4, snowflake и webtunnel bridge-строки). Feed ограничен 64 KiB; неподдерживаемые строки отбрасываются.
- Проверка выполняется при старте, если сохранённый список старше 7 дней, затем каждые 6 часов. При изменении списка Tor перезапускается и применяет обновлённые мосты; если feed временно недоступен, остаётся последний сохранённый список.
- Самостоятельное получение новых приватных мостов из BridgeDB не автоматизируется: Tor Project может требовать прохождения проверки при выдаче мостов. Используйте адрес feed, который вы контролируете и имеете право использовать.
- Если мосты не заданы, Tor подключается к публичной сети обычным способом.

## Обычные upstream

`upstreams` поддерживает `http://`, `https://`, `socks5://` и `socks5h://`; логин/пароль можно указывать в URL. Tor добавляется в тот же пул, где действуют ротация, failover и cooldown. SOCKS5 upstream с username/password пока не поддерживается; Tor SOCKS5h использует локальное соединение без внешней авторизации.

## Безопасность и ограничения

- Listener привязан только к loopback; не открывайте его в локальную сеть.
- Не публикуйте `config.json`, если в нём есть пароли или приватные bridge-строки.
- В архиве нет серверных адресов, серверных credentials или готового приватного списка мостов.
- Tor не делает автоматически анонимным весь компьютер: через локальный пул направляется только трафик приложений, которые используют заданный HTTP(S)-proxy. Не следует считать Tor заменой безопасным настройкам самого приложения.
- Обычный режим без Tor остаётся доступен: выключите `tor.enabled` и задайте собственные `upstreams`.
