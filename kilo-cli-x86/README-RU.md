# Kilo Code CLI 7.8.17 — Windows x86 (IA-32)

Порт Kilo Code CLI для Windows 10 x86 (версия 1809 или новее) и совместимых более новых систем. В архив включён полноценный CLI с интерактивным терминальным интерфейсом TUI, локальным сервером и командами управления моделями, провайдерами, сессиями, MCP и плагинами. Отдельно устанавливать Node.js не нужно: используется комплектный Node.js 22.23.0 для Windows x86.

## Установка

1. Распакуйте **весь** архив в отдельную папку.
2. Запустите `install.bat` (права администратора не нужны).
3. Установщик скопирует Kilo в `%LOCALAPPDATA%\Programs\KiloCLI` и добавит эту папку в пользовательский `PATH`.
4. Закройте и снова откройте PowerShell или CMD.
5. Проверьте установку:

```powershell
kilo --version
kilo --help
```

После установки команда `kilo` доступна из любого рабочего каталога. Для запуска интерфейса откройте терминал в папке проекта и выполните:

```powershell
kilo
```

Если не хотите добавлять программу в `PATH`, можно запускать `kilo.cmd` прямо из распакованной папки.

## Основные команды

| Команда | Назначение |
|---|---|
| `kilo` | Интерактивный терминальный интерфейс TUI |
| `kilo run "задача"` | Выполнить задачу без основного TUI |
| `kilo serve` | Запустить локальный сервер Kilo |
| `kilo attach <url>` | Подключиться к работающему серверу |
| `kilo auth` | Авторизация и управление провайдерами |
| `kilo models` | Список моделей |
| `kilo stats` | Статистика токенов и стоимости |
| `kilo session` | Управление сессиями |
| `kilo export` / `kilo import` | Экспорт и импорт сессий |
| `kilo mcp` / `kilo acp` | MCP и Agent Client Protocol |
| `kilo plugin` | Управление плагинами |
| `kilo agent` | Управление агентами |
| `kilo github` / `kilo pr` | Инструменты GitHub и pull request |
| `kilo cloud` | Cloud Agent |
| `kilo config` / `kilo db` | Конфигурация и база данных |
| `kilo worktree` | Git worktrees |
| `kilo completion` | Генерация автодополнения командной оболочки |
| `kilo help <command>` | Справка по конкретной команде |

В сборке также сохранены команды `debug`, `upgrade`, `uninstall`, `console`, `roll-call`, `profile`, `auto`, `remote` и `daemon`.

## Основные параметры

- `-m, --model provider/model` — выбрать модель.
- `-c, --continue` — продолжить последнюю сессию.
- `-s, --session <id>` — открыть указанную сессию.
- `--fork` и `--cloud-fork` — продолжить в отдельной ветке / получить облачную сессию.
- `--worktree <name>` — использовать Git worktree.
- `--prompt <text>` и `--agent <name>` — задать запрос и агента.
- `--mini`, `--no-replay`, `--replay-limit <n>` — параметры минимального интерфейса и истории.
- `--pure` — запуск без внешних плагинов.
- `--port`, `--hostname`, `--mdns`, `--mdns-domain`, `--cors` — параметры локального сервера.
- `--print-logs`, `--log-level` — управление журналированием.
- `-h, --help` и `-v, --version` — справка и версия.

Полный актуальный для этой сборки список параметров выводится командой `kilo --help`; справка подкоманды — `kilo help <command>`.

## Встроенный KiloProxyPool + Tor

В сборку включён автономный KiloProxyPool и официальный Tor Expert Bundle для Windows x86 (IA-32). Tor запускается локально вместе с Kilo, предоставляет SOCKS5h на `127.0.0.1:19050` и автоматически добавляется в пул. Kilo направляет сетевые запросы через локальный HTTP-прокси с Basic-аутентификацией. Сервер владельца не используется.

### Запуск с Tor — флаг `--proxy`

Самый простой способ — запустить Kilo с флагом `--proxy`:

```powershell
kilo --proxy
kilo --proxy run "Сделай TODO из этого файла" --model kilo/kilo-auto/free
kilo --proxy serve --port 4096
```

Флаг `--proxy` включает локальный прокси-пул и Tor. Никакой правки `config.json` не требуется — настройки применяются в режиме реального времени. Kilo запустится только после того, как Tor успешно подключится к сети.

### Без Tor — флаг `--no-proxy`

Если Tor не нужен (например, на чистой сети), запустите Kilo с флагом `--no-proxy` — прокси-пул и Tor запускаться не будут:

```powershell
kilo --no-proxy
```

### По умолчанию

Если ни `--proxy`, ни `--no-proxy` не указаны, поведение определяется `proxy/config.json` (по умолчанию в этой сборке `enabled: true` и `tor.enabled: true`, то есть Tor активен). Чтобы изменить поведение по умолчанию, отредактируйте `proxy/config.json`:

- `enabled: true` и `tor.enabled: true` — Tor всегда запускается (поведение по умолчанию);
- `enabled: false` — Tor не запускается, но можно временно включить флагом `--proxy`.

### Автообновление мостов

В `proxy/config.json` уже задан `tor.bridgeFeedUrl`, указывающий на публичный feed мосты obfs4 (`scriptzteam/Tor-Bridges-Collector` на GitHub). При запуске и затем каждые 6 часов Kilo:

1. Скачивает свежий список мостов (~7000 строк, выбираются случайные 60);
2. Если список изменился — перезаписывает локальный кэш `proxy/tor/data/bridge-cache.json`;
3. Если Tor запущен — перезапускает его с новым списком;
4. Если свежий feed недоступен — использует последний сохранённый список.

Если при запуске Tor не смог подключиться (мосты оказались нерабочими/заблокированными), Kilo форсирует обновление мостов и перезапускает Tor один раз. Если и вторая попытка не удалась — выводится ошибка и процесс завершается с кодом 78.

### Расширенный режим

`--proxy-debug` — включает детальный лог Tor-стадии инициализации (полезно при отладке):

```powershell
kilo --proxy --proxy-debug
```

### Ручная настройка (опционально)

Для тонкой настройки скопируйте `proxy\config.example.json` в `proxy\config.json` и отредактируйте:

- `clientAuth.username` / `clientAuth.password` — реквизиты Basic-аутентификации локального пула;
- `tor.exclusive: false` и `upstreams: [...]` — добавить к Tor обычные upstream HTTP/HTTPS/SOCKS5/SOCKS5h;
- `tor.bridges: ["Bridge obfs4 IP:port FINGERPRINT cert=... iat-mode=0", ...]` — вручную задать мосты;
- `tor.bridgeFeedUrl: ""` — отключить автообновление.

Подробности и ограничения — в `proxy\README-RU.md`. Не распространяйте `config.json`, если в нём находятся пароли или приватные bridge-строки.

## Удаление

Запустите `%LOCALAPPDATA%\Programs\KiloCLI\uninstall.ps1` через PowerShell с `-ExecutionPolicy Bypass`. Скрипт удалит программу из `Programs\KiloCLI` и уберёт её из пользовательского `PATH`; данные пользовательских сессий и настройки он не удаляет.

## Состав и ограничения

- Windows x86 / IA-32, PE32.
- `node.exe` — Node.js 22.23.0 win-x86.
- `kilo.cmd` — точка входа команды `kilo`; запускает `kilo-main.mjs` с compatibility layer.
- `kilo-main.mjs` и локальные зависимости Kilo CLI.
- OpenTUI runtime `@opentui/core-win32-ia32` и Koffi `win32_ia32`.
- Worker-модули, WASM-парсеры и tree-sitter ресурсы.
- Все native-модули в комплекте предназначены для IA-32; 64-битные native-модули не используются.

Это именно CLI-порт, а не Kilo Desktop/Electron. Исходный `Kilo-Setup-x64.exe` на сервере относится к отдельному Desktop-пакету 0.1.15; он не является CLI 7.8.17. Здесь сохранён набор команд и параметров CLI, который запускается командой `kilo`; Electron/Desktop-интерфейс в эту сборку не входит.

Версия CLI в этой сборке — 7.8.17. Команда `kilo upgrade` сохранена, но для IA-32 лучше обновляться новым x86-архивом: upstream-обновление может не содержать 32-битный runtime. Архив проверялся под Wine с 32-битными PE-файлами; запуск установщика и полная визуальная проверка TUI на физической 32-битной Windows всё ещё требуют финальной проверки на самом устройстве.
