Kilo Code CLI 7.8.17 — Windows 10 x86 (1809+) / IA-32

Runtime: Node.js 22.23.0 win-x86
Architecture: PE32 / Intel 80386
Package: portable ZIP + install.bat / install.ps1
Installed command: kilo (kilo.cmd on PATH)
Install target: %LOCALAPPDATA%\Programs\KiloCLI

Interactive TUI port:
- OpenTUI native runtime: @opentui/core-win32-ia32/opentui.dll (PE32)
- Koffi native module: win32_ia32 only
- IA-32 node-pty / ConPTY and Parcel watcher native modules
- Node worker_threads bridge for Kilo TUI/indexing/session workers
- SolidJS Node export patched to use the client/web runtime, not SSR server runtime
- Node/Bun compatibility layer
- No x64 native modules included

Installation:
- install.bat invokes install.ps1 without requiring administrator rights
- install.ps1 copies the complete runtime and adds the install directory to the current user's PATH
- kilo.cmd starts the bundled 32-bit Node runtime and forwards all CLI arguments
- uninstall.ps1 removes the installed application and PATH entry, leaving user data untouched

Scope:
- This is the Kilo CLI port, not the Kilo Desktop/Electron application.
- The separate Kilo-Setup-x64.exe present in the source workspace is Desktop 0.1.15, not this CLI package.

Local proxy adapter:
- proxy/manager.cjs validates local HTTP/HTTPS proxy configuration and waits for its TCP endpoint
- proxy/launcher.cjs starts optional local proxy process, injects HTTP_PROXY/HTTPS_PROXY, runs Kilo, then stops the child process
- proxy/config.json ships enabled by default with Tor; config.example.json contains a placeholder local password
- HTTP CONNECT supported; SOCKS5 requires a local HTTP CONNECT bridge
- adapter smoke-tested on host Node and bundled Node under Wine; physical Windows x86 validation remains outstanding

Embedded KiloProxyPool (Node.js, no Python dependency):
- Local loopback listener with Basic client authentication (HTTP 407 for unauthenticated clients)
- Upstream pool: HTTP, HTTPS, SOCKS5, SOCKS5h; rotation, failover, exponential cooldown and success reset
- HTTP CONNECT tunnelling and HTTP forwarding; local pool lifecycle tied to kilo.cmd
- No owner-server endpoint or credentials included; shipped config enables Tor and has an empty upstream pool
- Host smoke tests passed: authenticated CONNECT via mock SOCKS5h upstream and unauthenticated rejection
- SOCKS5 upstream username/password authentication not yet supported; physical Windows x86 acceptance remains outstanding

Embedded Tor + KiloProxyPool:
- Official Tor Expert Bundle 16.0 / Tor 0.4.9.15 for Windows i686 (PE32), signature verified with Tor Browser Developers signing key
- Bundled tor.exe, lyrebird.exe (pluggable transports), conjure-client.exe, GeoIP and GeoIPv6 databases
- Tor starts with Kilo, waits for 100% bootstrap, exposes SOCKS5h on loopback and is stopped with Kilo
- Tor SOCKS5h is automatically included as an upstream in the local authenticated proxy pool
- Optional static bridges and weekly HTTPS bridge-feed refresh with cache and rollback on failed Tor restart
- No owner-server proxy endpoint, credentials or private bridge list included; Tor is enabled in shipped config with placeholder local authentication
- Tor binary version checked under Wine; full Tor network bootstrap and physical Windows x86 acceptance still require end-to-end testing
