Kilo Code CLI 7.8.17 — Windows 10 x86 (1809+) / IA-32 (Tor-enabled build)

Runtime: Node.js 22.23.0 win-x86
Architecture: PE32 / Intel 80386
Package: portable ZIP + install.bat / install.ps1
Installed command: kilo (kilo.cmd on PATH)
Install target: %LOCALAPPDATA%\Programs\KiloCLI

Interactive TUI port (with koffi-ffi-adapter fix):
- OpenTUI native runtime: @opentui/core-win32-ia32/opentui.dll (PE32)
- Koffi native module: win32_ia32 only
- koffi-ffi-adapter patched: makeCallbackProto() with try/catch fallback to
  process-unique name when 'Duplicate type name kilo_callback' is thrown
  (happens when @opentui/core is imported in multiple worker_threads —
  Koffi's type registry is process-global but the module-level
  callbackSequence counter resets per import).
- toArrayBuffer() coerces BigInt/Boolean/Number length to integer with
  explicit TypeError on invalid input (was: "Unexpected Boolean value for
  length, expected integer" from Koffi).
- IA-32 node-pty / ConPTY and Parcel watcher native modules
- Node worker_threads bridge for Kilo TUI/indexing/session workers
- SolidJS Node export patched to use the client/web runtime, not SSR server runtime
- Node/Bun compatibility layer
- No x64 native modules included

Autonomous Tor proxy pool (proxy/launcher.cjs + proxy/manager.cjs):
- Bundled Tor Expert Bundle for Windows i686 (Tor 0.4.9.15):
  tor.exe, lyrebird.exe (obfs4/snowflake/webtunnel), conjure-client.exe,
  geoip/geoip6 databases.
- Local HTTP CONNECT proxy pool on 127.0.0.1:17890 with Basic auth
  (kilo / kilo-local-tor-pool — change in proxy/config.json).
- Tor SOCKS5h listener on 127.0.0.1:19050, added as exclusive upstream.

Launcher flags:
- kilo                : default — Tor started (config.json has enabled:true, tor.enabled:true).
- kilo --proxy        : force-enable Tor + proxy pool even if config.json has them disabled.
- kilo --no-proxy     : skip the proxy pool entirely (fast startup, no Tor bootstrap).
- kilo --proxy-debug  : verbose Tor + proxy pool logging (KILO_LOG_LEVEL=debug).

Bridge auto-refresh:
- bridgeFeedUrl defaults to https://raw.githubusercontent.com/scriptzteam/Tor-Bridges-Collector/master/bridges-obfs4
  (public feed of ~7000 obfs4 bridges, updated hourly by GitHub Actions).
- parseBridges() accepts both 'Bridge obfs4 IP:port FINGERPRINT cert=...' and
  'obfs4 IP:port FINGERPRINT cert=...' (no prefix) — normalises to prefixed form.
- updateBridges() downloads the feed, deduplicates by transport+host+port+fingerprint,
  shuffles and caps to 60 bridges (Tor's torrc accepts many, but each adds a
  TLS handshake during bootstrap — 60 keeps startup reasonable).
- Cache file: proxy/tor/data/bridge-cache.json (1-week TTL, refreshed every 6 hours).
- On Tor bootstrap timeout (240s default) → restartTorWithFreshBridges() forces a
  fresh fetch (ignoring cache) and restarts Tor once. If retry also fails, exit code 78.

Installation:
- install.bat invokes install.ps1 without requiring administrator rights.
- install.ps1 copies the complete runtime and adds the install directory to the current user's PATH.
- kilo.cmd starts the bundled 32-bit Node runtime and forwards all CLI arguments.
- uninstall.ps1 removes the installed application and PATH entry, leaving user data untouched.
